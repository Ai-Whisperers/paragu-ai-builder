# Plan: Eliminate TypeScript `as any` Escapes

## Current State

`as any` casts are scattered across the codebase as escape hatches. The most critical ones:

### Business Data (P0)

```typescript
// app/api/tenant/[businessId]/content/route.ts:26
const existing = (business?.data_json as any) || {}

// app/dashboard/[slug]/contenido/page.tsx:29
initialContent={(business?.data_json as any)?.content || {}}
```

These exist because `data_json` is typed as `Json` (Supabase generic) when it should be a strongly-typed `BusinessContent` type.

### Section Component (P1)

```typescript
// components/sections/forms/subscription-section.tsx:83
products={(products || []) as any}
```

This was a quick fix during the refactor session to match incompatible product types.

## Root Cause

1. `data_json` column in Supabase `businesses` table is typed as `Json` → any access requires casting
2. The `BusinessContent` type exists in `lib/commerce/business-content.ts` but isn't wired into Supabase type generation
3. Some component prop types are incompatible with their callers — `any` was the path of least resistance

## Proposed Fixes

### Fix 1: `data_json` → Strongly Typed

**Step 1**: Check if Supabase types are generated:

```typescript
// web/lib/supabase/client.ts
import { createClient } from '@supabase/supabase-js'
import type { Database } from './generated/types'  // generated by supabase gen types
```

If `supabase gen types` hasn't been run, add it:

```bash
npx supabase gen types typescript --project-id qyvokpribmbrosafntqa > web/lib/supabase/generated/types.ts
```

**Step 2**: Create a helper for typed `data_json` access:

```typescript
// web/lib/business-content.ts
import type { BusinessContent } from '@/lib/commerce/business-content'

export function getBusinessContent(business: { data_json: unknown }): BusinessContent {
  if (typeof business.data_json === 'object' && business.data_json !== null) {
    return business.data_json as BusinessContent
  }
  return {} as BusinessContent
}

// Usage:
const existing = getBusinessContent(business)
```

**Step 3**: Update the two escaping sites:

```typescript
// app/api/tenant/[businessId]/content/route.ts
import { getBusinessContent } from '@/lib/business-content'
const content = getBusinessContent(business)

// app/dashboard/[slug]/contenido/page.tsx
import { getBusinessContent } from '@/lib/business-content'
initialContent={getBusinessContent(business).content || {}}
```

### Fix 2: Subscription Product Types

The issue: `SubscriptionSection` passes `products` to `SubscriptionForm`, but they have incompatible types.

```typescript
// SubscriptionSection passes: Array<{ name: string; price: string }>
// SubscriptionForm expects: Array<{ id: string; name: string; price: number; unit: string }>

// Fix: Align the types
export interface SubscriptionSectionProps {
  products?: Array<{
    id: string
    name: string
    price: number
    unit: string
  }>
}
```

Or, if the section doesn't have IDs/units, map them:

```typescript
const mappedProducts = (products || []).map((p, i) => ({
  id: String(i),
  name: p.name,
  price: Number(p.price) || 0,
  unit: 'unidad',
}))
```

## Audit Process

Find all remaining `as any` usages:

```bash
grep -rn "as any\b" web/ --include='*.ts' --include='*.tsx' | grep -v node_modules | grep -v '.next' | grep -v 'generated/'
```

Categorize each by fix type:
- **Type assertion needed**: `value as Type` (replace `as any` with proper type)
- **Missing helper**: `business.data_json as any` (use typed accessor)
- **Legitimate escape**: `JSON.parse as any` (rare, document with comment)
